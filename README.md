# Плагины Koda Desktop

Каталог плагинов для Koda Desktop.

* Официальный сайт: <https://kodacode.ru>
* Скачать Koda Desktop: <https://download.kodacode.ru>
* Сообщество в Telegram: [@kodacommunity](https://t.me/kodacommunity)

## Введение

**Плагины** добавляют в Koda Desktop новые возможности: панель рядом с чатом, отдельный раздел в боковом меню, инструменты для агента, упоминания в поле ввода и настройки.

Плагин распространяется архивом `.kodaplugin`. Его основная часть работает в изолированной песочнице, а интерфейс открывается в отдельном изолированном представлении без доступа к сети. Всё, что плагину нужно сверх этого (файлы проекта, инструменты агента, сеть, уведомления), он запрашивает в манифесте, и Koda показывает этот список перед установкой.

Код плагинов хранится в репозиториях авторов. Этот репозиторий содержит только каталог: ссылки на собранные архивы и их SHA-256.

## Быстрый старт

1. Откройте Koda Desktop и нажмите **Маркетплейс** в боковом меню.
2. Перейдите на вкладку **Плагины** и выберите плагин.
3. Проверьте список разрешений и подтвердите установку.

Koda скачивает архив по ссылке из каталога, сверяет SHA-256 и устанавливает плагин. Если хеш не совпал, установка отменяется.

## Установка

Плагины можно установить тремя способами:

| Способ | Где |
| --- | --- |
| **Из маркетплейса** | Маркетплейс → Плагины |
| **Из файла** | Маркетплейс → Установленные → Установить из файла (`.kodaplugin`) |
| **Папка для разработки** | Маркетплейс → Установленные → Подключить папку для разработки |

Подключённая папка перезагружается при каждом изменении файлов. Этот способ нужен авторам плагинов.

Установленный плагин можно выключить, настроить или удалить в разделе **Маркетплейс → Установленные**. Там же видны встроенные плагины (Потоки, Браузер, Git, Задачи): их можно только выключить.

## Разрешения

Плагин получает только те разрешения, которые перечислены в его манифесте:

| Разрешение | Что даёт |
| --- | --- |
| `project.read` | Чтение файлов проекта |
| `project.write` | Запись файлов проекта |
| `agent.tools` | Собственные инструменты для агента |
| `agent.run` | Запуск агента, который может только читать |
| `chat.composer` | Вставка текста в поле ввода чата |
| `chat.context` | Упоминания плагина в поле ввода |
| `notifications` | Уведомления |
| `secrets` | Хранение секретов |
| `process.run` | Запуск файла проекта известным интерпретатором (python, node, go, ruby, php) |
| `network:<host>` | Запросы к указанному хосту |

## Как добавить плагин

1. **Создайте** плагин из шаблона [KodaPluginTemplate](https://github.com/XCode-NLP/KodaPluginTemplate) (кнопка «Use this template»). SDK и команда `koda-plugin` ставятся вместе с шаблоном.
2. **Выпустите релиз**: поставьте тег вида `v1.0.0`. GitHub Actions соберёт архив и приложит его к релизу вместе с файлом `SHA256SUMS`.
3. **Сделайте форк** этого репозитория и добавьте файл `plugins/<id>.json`, где `<id>` совпадает с `id` в `koda-plugin.json`.
4. **Откройте pull request**. CI скачает архив, сверит SHA-256 и проверит манифест. Мейнтейнеры посмотрят код плагина и его разрешения.

Чтобы выпустить обновление, выпустите новый релиз и пришлите PR, где в `plugins/<id>.json` заменены `url` и `sha256`. Опубликованный архив не перезаписывают: у новой версии свой тег.

## Формат записи

```json
{
  "id": "com.example.my-plugin",
  "homepage": "https://github.com/you/my-plugin",
  "archive": {
    "url": "https://github.com/you/my-plugin/releases/download/v1.0.0/com.example.my-plugin-1.0.0.kodaplugin",
    "sha256": "da470071cd83482e7841967224bd045686f6687889b38a5741cc8867949c3e33"
  }
}
```

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `id` | да | Id из манифеста; файл называется `<id>.json` |
| `homepage` | нет | Страница плагина, только `https://` |
| `archive.url` | да | Ссылка на архив `.kodaplugin`, только `https://` |
| `archive.sha256` | да | SHA-256 архива, 64 символа в нижнем регистре |

Другие поля в записи не допускаются. Имя, описание, версию, издателя и разрешения CI берёт из манифеста внутри архива, поэтому дублировать их не нужно.

**Требования к id**: латинские буквы в нижнем регистре и цифры, сегменты разделяются точкой или дефисом.

- ✅ Валидно: `com.example.my-plugin`, `dev.koda.companion`
- ❌ Невалидно: `Com.Example` (верхний регистр), `.my-plugin` (точка в начале), `my..plugin` (двойная точка)

## Обслуживание репозитория

### Автоматическая проверка и обновление

В pull request срабатывает workflow `.github/workflows/check.yml`. Он скачивает каждый архив из `plugins/`, сверяет SHA-256, распаковывает архив, проверяет манифест командой `koda-plugin validate` и сверяет `id` в манифесте с записью.

При пуше в ветку `main` или слиянии pull request срабатывает workflow `.github/workflows/publish.yml`, который:

1. Выполняет те же проверки и собирает `metadata.json`
2. Создаёт коммит с обновлённым `metadata.json`, если каталог изменился
3. Использует сообщение `chore: update metadata.json`

### Команды

```bash
npm ci          # установить SDK @kodadev/desktop-plugin-sdk (из Nexus, адрес в .npmrc)
npm run check   # проверить все записи, не меняя metadata.json
npm run build   # проверить записи и записать metadata.json
```

### О файле metadata.json

Файл `metadata.json` содержит все плагины каталога. Koda Desktop читает его по адресу <https://raw.githubusercontent.com/XCode-NLP/KodaPlugins/main/metadata.json>. Файл собирает CI, вручную его не правят.

```json
{
  "lastUpdate": "2026-11-17T17:34:16.917Z",
  "plugins": [
    {
      "id": "com.example.hello",
      "name": { "ru": "Привет", "en": "Hello" },
      "description": {
        "ru": "Пример плагина: панель рядом с чатом и инструмент агента.",
        "en": "Example plugin: a pane next to the chat and an agent tool."
      },
      "version": "1.0.0",
      "publisher": "Koda Examples",
      "permissions": ["agent.tools", "chat.composer"],
      "homepage": "https://github.com/you/hello",
      "archive": {
        "url": "https://github.com/you/hello/releases/download/v1.0.0/com.example.hello-1.0.0.kodaplugin",
        "sha256": "a804257a23287086691f365bc4ae44e1dbbbb58efe4a73d2864e1193182d6118",
        "size": 4490
      }
    }
  ]
}
```

Поля `name`, `description`, `version`, `publisher` и `permissions` берутся из `koda-plugin.json` внутри архива. `size` содержит размер архива в байтах. Архив больше 60 МБ не проходит проверку, потому что установщик Koda Desktop его тоже отвергнет.

`lastUpdate` меняется только вместе со списком плагинов, поэтому повторная сборка без изменений не создаёт коммит.
